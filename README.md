# 模型 API 错误诊断

面向 DSH `0.2.2-rc.5` 的 Host 插件。打开 **插件 → 添加插件**，选择此包所在目录。不需要依赖、构建、额外凭据或配置。

- **聊天**：沿用 DSH 自带的失败提示；请求最终失败时，给原有提示补充排查建议、供应商、模型、错误码、HTTP 状态码、Request ID 和 Retry-After（仅显示可用字段）。DSH 可能为部分已知错误显示固定文案，尤其是 `AUTH`；对应诊断可在后台日志查看。
- **文件日志**：固定保存在当前系统用户主目录下的 `~/.dsh/logs/api-diagnostics.jsonl`，不随 DSH 配置、工作区或插件安装位置变化。Windows 可在文件资源管理器地址栏输入 `%USERPROFILE%\.dsh\logs`；例如，用户 `Alice` 的默认路径是 `C:\Users\Alice\.dsh\logs\api-diagnostics.jsonl`。旧版本在 DSH 配置目录下生成的日志不会自动迁移。第一次错误时自动创建，UTF-8 编码，每次失败一行 JSON。记录 UTC 时间、供应商、模型、错误码、HTTP 状态、Request ID、建议重试等待毫秒数、脱敏后的详细原因（最多约 4096 字符）及排查建议。自动重试成功前发生的失败也会记入，不记录成功请求或主动取消。达到约 5 MiB 时轮转，只保留上一份 `api-diagnostics.jsonl.1`。
- **后台日志**：仍可搜索 `[api-diagnostics]`。若磁盘写入失败，插件只向 Host 报告文件错误码，不中断原有错误处理。

不修改重试决策，也不会把工具错误或用户主动取消归为模型 API 故障。认证类失败（包括 HTTP 401/403）不记录上游原文；其余错误做常见凭据和 URL 脱敏、移除控制字符并截断。脱敏不是完整的敏感信息检测，共享日志前请再检查。该插件只覆盖经过 DSH 模型流且产生错误结束帧的请求，不捕获整个应用内的所有 HTTP 请求。
